Does prompt optimization make a RAG system more correct?

An evaluation of DSPy on a small retrieval-augmented generation (RAG) pipeline that runs fully offline

Nikita SinghCode: github.com/Singhniku/dspy-rag

I built this to learn how language models answer questions and how those answers should be measured. DSPy tunes a pipeline's prompts automatically, so I tested whether the tuning made the answers more correct, or only better on the score it was tuned for.

What this project is

  • A question-answering pipeline over a fictional company's policies, running fully offline on my laptop
  • A controlled experiment: held-out questions, five seeds per setup, paired-bootstrap confidence intervals
  • A behavioral test suite, modeled on CheckList, that looks for how the system fails
  • Public and checkable: code, data, every answer and every grade

What it is not

  • Not connected to my job: built outside work on my own laptop, with made-up documents and questions
  • Not model training: the weights never change; DSPy only rewrites the prompt and picks examples
  • Not a benchmark claim: the test set is small, so the 95% intervals on correctness span about ±0.09
  • Not hand-graded: the correctness review was done with Claude; every grade is published beside the 7B judge's

How it works

Every setup answers with the same pipeline. The optimizers change only the prompt inside the DSPy module.

The experiment

58 gold questions, split once by type

3 setups × 5 seeds = 15 runs

Optimizers recompiled for every seed. About 10 hours on an M3 MacBook Air.

What I scored

  • Correctness: 1, 0.5 or 0 per answer, reviewed
  • Similarity to the gold answer, which the optimizers maximize
  • RAGAS faithfulness and answer relevancy
  • 110 behavioral tests: paraphrased, negated and unanswerable questions

What I found

Baseline, no optimizerBootstrapFewShotMIPROv2

1Similarity rose; correctness stayed within noise

Similarity is the score the optimizers maximize, and much of its gain came from longer answers. The intervals for correctness include zero, though 9 of the 10 optimized runs beat the baseline.

2The gain was all single-hop

Travel meal allowance? Baseline: “$75.” Optimized: “$75 in North America and €70 in Europe.”

Multi-hop got slightly worse, and retrieval was not the cause (context recall 0.97).

3Fewer fragile answers, the same hallucinations

A near-miss question sits next to a covered fact: the auto-lock rule is for laptops, and the test asks about phones. The model applied the neighboring rule instead of declining.

4Perfect scores for wrong answers

Of the baseline's 11 failing test answers, RAGAS gave 4 a perfect faithfulness score.

What I learned

  1. Optimize the behavior you want. Similarity rewarded longer, gold-like phrasing, so the optimizers mostly changed style.
  2. Test how a system fails. Averages looked healthy (faithfulness 0.96, recall 0.97) while 31% of negated questions failed.
  3. Check the grader. An LLM judge is a model too: on multi-hop answers it matched the review 58% of the time.

What I would do next

  1. About 4× more test questions, many of them multi-hop, so a 0.05 gain is detectable
  2. Optimize for correctness (complete, no contradictions) instead of similarity
  3. Pin the “decline if not covered” rule and add negated and near-miss questions to training
